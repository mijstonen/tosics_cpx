Make PHP directives aware, so it can be used to serve PHP preprocessing.
How: preparsing prehash on directive lines, injecting commands to PHP

# 123 "path/to/file" d ...

transformed to:

<?InhectDirective(<<<EODL
# 123 "path/to/file" d ...
EODL);?>

The default output to transformed is to reproduce the directive unmodified.

Overview of uPP commands by token (order is left to right, top down on keyboard)

#~     [new idea] ..... something like resource deallocation cutomization .....
#`     [new idea] ..... Smart library binding allows to specify in the libraries (aka pkgconfig for Qt)
#!     first line: hash bang for running the script, all other lines, start of main, it puts the rest of the file in main, or till the next uPP token. Every following #! will create a peer parallel forked cpx::main, but then cpx::vector<main_func>[] 1, 2, .... N which each will run in its own forked process.

#!?    querying meta command, every call might produce different results despite equal arguments, unconditionally always execute
#!=    pure execution, if previously arguments are reused, the prior compiled and hashed executabele can be reused.
#!&      [reserved] Asynchronous execute child program
#!&<trigger>  same as #!& but trigger will be submitted when child program is completed. There is no other information passing mechanism for this in uPP
#!,      [reserved] synchronization ANY:Wait for one of Asynchronous child programs to complete
#!.      [reserved] AND:Wait for all Asynchronous child programs to complete
#%
#$
#o     OMP directive it is replaced by "#pragma omp"     "#o parallel" ->  "#pragma omp parallel"

#@     forced source line marking

##     nested scope.   The following scopes are counted by uPP
        (  +1    )   -1     symetric counts forC like language syntax
        [  +1    ]   -1
        {  +1    }   -1

        /* +1    */  -1     disbale/enable counts above
        // +1   '\n' -1

        <? +1    ?>  -1  php scope counts, not effected by comment tokens above

        The effect of the changes made in the nested scope is only as long the scope counts do not go below the
        current counts.
        This is archived by running uPP and slave processes in a child process.

        example

            foo()
            {
        #%
         # define LOCAL 2

                use of LOCAL
            }

        // scope count is decreased
        cannot use LOCAL here

        Remarks: Some edge cases are not handled or should be implemented later.
        * Nested scopes can be (recursively) nested again
        * Nested scopes do know the encapsulated environment, you cannot shadow symbols or variables (without special precautions,like use of #undef).
        * \ before new line, when in // the status of next line is undefined. Simplest is to ignore it and start with a fresh new line.
        * using # for comments in php. You can use it, but uPP would not know,consider it an active php code part.
          it will only cause problems when asymetrically using ({[]}) <? ?> inside such comment.
          To be save, only use C/C++ style comments inside php code.

#/       file wide search and replace, introduced where this uPP command starts, it does not act inside uPP commands
            options can be similar to sed, option w is to replace words only where words are sparated by spaces and
            (typical C) tokens. Replace substitutions run first and on the fly (before the C++ processor)
            They ONLY act on the file it self not on included or sourced files.

#/=

#<       [new idea] ....(binary) output stream...... ?

#>       [new idea] ....(binary) input stream...... ?

#?<trigger> [new idea] completion code as response Asynchronous started child program. If this token happens multiple times, all completion code parts will be executed in isolation and (possibly) in parallel each in their own context. It usually means that the child process that produced its results broadcasts these same results to all completers that where triggered. However each of the completers may also have some own context and behave differently.
